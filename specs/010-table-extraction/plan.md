# Implementation Plan: Table Extraction

**Branch**: `010-table-extraction` | **Date**: 2026-09-19 | **Spec**: [spec.md](file:///d:/Coding/LearnSpecKit/Proj1/specs/010-table-extraction/spec.md)

**Input**: Feature specification from `specs/010-table-extraction/spec.md`

## Summary

Add a new "Table" rule type (`TABLE`) to the extraction engine to enable extracting structured tabular data from PDF files. Users can define a table bounding box on the PDF canvas and configure advanced extraction strategies (bordered/borderless, vertical/horizontal strategies, header row counts, snap tolerances). The feature uses PyMuPDF (`fitz.Page.find_tables()`) for engine extraction without adding heavy external dependencies, models rules cleanly using Pydantic v2, and flattens extracted 2D table structures into JSON strings within the main CSV output during batch processing.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: PySide6 (>=6.6.0), PyMuPDF (>=1.23.0), Pydantic (>=2.4.0), pytest (>=7.4.0), pytest-qt (>=4.2.0)
**Storage**: Local template JSON files (`.json`) and batch export CSV files (`.csv`)
**Testing**: `pytest`, `pytest-qt`
**Target Platform**: Windows / Desktop (PySide6)
**Project Type**: Desktop Application
**Performance Goals**: < 1.0s table extraction time per PDF page in batch processing mode
**Constraints**: Decoupled parsing logic (no UI dependencies in strategy/engine), Pydantic v2 discriminated union serialization, no new third-party binary/runtime dependencies (e.g. Java, OpenCV)
**Scale/Scope**: Single-page table region extraction per rule in MVP
